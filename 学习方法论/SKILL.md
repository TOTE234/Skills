# Learning Method — 快速掌握新技能方法论

## 核心理念

本方法论基于五个关键原则：

1. **80/20 法则（帕累托法则）**：20% 的核心内容覆盖 80% 的使用场景，先学这 20%。
2. **资源精筛**：从海量学习资源中挑出最值得投入的少数几个，明确每个资源"该看哪里"和"不该看哪里"，避免时间浪费。
3. **刻意练习 + 即时反馈**：每学一个知识点，立即通过问题检验，当场纠正。
4. **费曼学习法**：用自己的话把概念讲给别人听，讲不清就是没懂；通过多轮"讲解→反馈→重讲"逼近真正理解。
5. **输出倒逼输入**：用速查表作为最终输出物，迫使学习者提炼精华、发现盲区。

整个流程是一个闭环：

```
目标分析 → 内容筛选 → 资源筛选与路径设计 → 划分等级 → 逐个攻克
→ 苏格拉底测验 → 费曼讲解验证 → 制作速查表 → 最终自测
```

---

## 适用场景

当用户表达以下意图时使用本 Skill：

- "我想学习 [技能]，请帮我制定学习计划"
- "如何在 [时间] 内掌握 [技能]？"
- "帮我设计一个从入门到精通的学习路径"
- "学完了，帮我总结一下"
- "我想系统学习 [某领域]"
- "有没有高效学习 [某技能] 的方法？"
- "帮我筛选学习 [某技能] 最值得看的资源" → Stage 2
- "我想用费曼学习法学 [概念]" → Stage 5

**不适用场景：**
- 用户只需要一个速查表（已有 `cheat-sheet` Skill）
- 用户只需要一个学习计划（已有更轻量的方式）
- 纯聊天/咨询，不涉及具体技能学习

## 完整七阶段工作流

### Stage 1: 目标分析与内容筛选（80/20 法则）

**目的**：在动手之前，明确"学什么"和"不学什么"。

#### 1.1 确定学习目标

向用户确认以下信息（通过提问）：

| 问题 | 为什么重要 |
|------|-----------|
| 你总共有多少时间？ | 决定计划粒度和内容取舍 |
| 你的起点是什么？（完全新手/有基础/有经验） | 决定从哪个等级开始 |
| 学完后想做什么？（做项目/应付考试/日常用） | 决定内容侧重 |
| 有没有截止时间？ | 决定强度和节奏 |

#### 1.2 80/20 内容筛选

对于目标技能，按以下标准筛选内容：

**必须包含的 20%（核心内容）**：
- 每天/每次都会用到的基础概念
- 不理解就无法继续的"前置知识"
- 占该技能 80% 使用场景的内容

**可以暂时跳过 80%（边缘内容）**：
- 高级/冷门的用法
- 有替代方案的冗余功能
- 实际工作中很少遇到的场景
- 可以在用到时再查文档的内容

**筛选工具**：问自己——"如果用户只学 10 个概念，哪 10 个最有用？"

#### 1.3 输出：学习计划

基于筛选结果，生成结构化的学习计划。

**计划格式**：
- 总时长：[X] 小时
- 分 [N] 次，每次 [X/N] 小时
- 每次包含：学习内容 + 练习任务 + 推荐资源 + 复盘要点

**示例结构**（以 20 小时 Python 为例）：

| 次数 | 主题 | 时长 | 核心内容 | 练习 | 资源 | 复盘 |
|------|------|------|----------|------|------|------|
| 1 | 变量与数据类型 | 2h | int/float/str/bool | 10题 | 文档链接 | 常见错误 |
| 2 | 运算符与输入输出 | 2h | + - * / // % ** | 小型计算程序 | 教程 | 类型转换 |
| ... | ... | ... | ... | ... | ... | ... |

**输出文件**：`templates/learning-plan.html` — 可视化的学习计划页面，带时间线、进度条、资源链接。

### Stage 2: 资源筛选与学习路径设计

**目的**：从海量学习资源中精选出最值得投入的少数几个，并基于这些资源设计可执行的天级学习路径。避免学习者在"找资源"上浪费时间，也避免"收藏了就等于学了"的陷阱。

#### 2.1 资源筛选原则

**筛选数量**：5 个资源，不多不少。太少视角单一，太多无法聚焦。

**每个资源必须回答 5 个问题**：

| 问题 | 说明 |
|------|------|
| 适合谁？ | 明确目标受众（新手/有基础/想进阶） |
| 难度如何？ | 入门 / 中级 / 高级 |
| 该怎么用？ | 作为主线 / 深度补充 / 实战练习 / 查漏补缺 |
| 重点看哪里？ | 标注最值得投入的章节/段落 |
| 不要浪费时间看哪里？ | 标注可跳过的冗余/过时/偏门内容 |

#### 2.2 资源类型搭配

5 个资源应覆盖不同角色，形成互补：

| 角色 | 作用 | 典型类型 |
|------|------|----------|
| 主线教材 | 系统推进知识体系 | 官方教程、经典教材 |
| 视频课程 | 提供直观讲解和节奏感 | 大学公开课、系列视频 |
| 实战项目 | 通过做真实任务巩固知识 | 项目驱动型书籍/教程 |
| 刻意练习 | 大量小题训练肌肉记忆 | 在线练习平台 |
| 专题深挖 | 针对薄弱点定向突破 | 博客文章、专题文档 |

#### 2.3 学习路径设计

将资源按天编排，每天 2-3 小时，形成可执行路径。

**每天的结构**：

```
学（输入） → 练（输出） → 盘（复盘）
```

- **学**：从主线教材/视频课程中学习当天主题
- **练**：在练习平台做对应题目，或在实战项目中完成当天任务
- **盘**：回顾当天学的概念，自问"如果给别人讲，我能讲清吗？"

**路径设计原则**：
- 每天聚焦 1-2 个核心概念，不要贪多
- 前 2 天打基础，中间 3 天进阶+实战，最后 2 天综合+复盘
- 每天的任务必须具体到"看哪一节""做哪几题"，不能是"学一下函数"

#### 2.4 完整示例：Python 精选资源 & 7天学习路径

以下是一个完整的真实案例，展示如何从筛选资源到设计路径。

**5 个精选资源**：

| # | 资源 | 角色 | 适合谁 | 难度 |
|---|------|------|--------|------|
| 1 | Python 官方教程 | 主线教材 | 所有人 | 入门-中级 |
| 2 | Harvard CS50P | 视频课程 | 喜欢视频教学 | 入门 |
| 3 | Real Python | 专题深挖 | 需要查漏补缺 | 中级 |
| 4 | Automate the Boring Stuff | 实战项目 | 想做实际项目 | 入门-中级 |
| 5 | Exercism Python Track | 刻意练习 | 需要动手练习 | 入门-中级 |

**每个资源的详细指引**：

**资源 1：Python 官方教程**
- 适合谁：所有人，作为主线教材从头到尾跟着走
- 难度：入门→中级（前几章简单，后面逐步加深）
- 怎么用：按章节顺序读，每读完一节立即在 REPL 中敲一遍示例代码
- 重点看：第 3 章（非正式介绍）、第 4 章（控制流）、第 5 章（数据结构）、第 8 章（错误处理）
- 不要看：第 1-2 章（安装说明，直接跳过）、第 9 章（虚拟环境，用到再学）、第 12 章（虚拟环境详细配置）

**资源 2：Harvard CS50P**
- 适合谁：喜欢有老师讲、有节奏感的人；完全新手
- 难度：入门
- 怎么用：每周 1-2 个 Lecture，边看边在编辑器里跟着敲
- 重点看：Lecture 0-6（变量、条件、循环、函数、列表、字典、文件 I/O、正则）
- 不要看：Lecture 7 及以后（面向对象、ETC 等，第二阶段再学）；Problem Set 中过于耗时的可以跳过

**资源 3：Real Python**
- 适合谁：学到某个概念没搞懂，需要换个角度解释的人
- 难度：中级（部分文章偏进阶）
- 怎么用：不要通读，当作"字典"——学到某个概念时搜索对应文章阅读
- 重点看："Strings and String Methods"、"Lists and Tuples"、"Dictionaries" 这几篇基础教程
- 不要看：关于 asyncio、装饰器、元类等高级主题的文章（第一周不需要）；每天最多读 1-2 篇，不要陷入"刷文章"的陷阱

**资源 4：Automate the Boring Stuff with Python**
- 适合谁：想快速做出"有用的小程序"的人；不喜欢纯理论
- 难度：入门→中级
- 怎么用：Day 5-6 跟着做真实项目（Excel 操作、网页抓取等）
- 重点看：第 1-6 章（基础语法+字符串）、第 13 章（Excel）、第 12 章（网页抓取）
- 不要看：第 17-20 章（GUI、邮件、API 等，用到再学）；每章末尾的"实践项目"选做 1-2 个即可，不必全做

**资源 5：Exercism Python Track**
- 适合谁：需要大量动手练习来巩固概念的人
- 难度：入门→中级（题目由易到难排列）
- 怎么用：每天做 3-5 道 Easy/Medium 题，用当天学到的概念解题
- 重点看：前 20 道 Easy 题（覆盖变量、函数、字符串、列表、字典等核心概念）
- 不要看：Hard 题和需要复杂算法的题；不要追求"全做完"，做 20 题左右就够了

**7 天学习路径**（每天 2-3 小时）：

| 天 | 主题 | 学 | 练 | 盘 |
|----|------|-----|-----|-----|
| D1 | 变量、数据类型与字符串 | 官方教程第3章 + CS50P Lecture 0 前30分钟 | Exercism 前3道 Easy 题 | str 和 int 有什么区别？`"5"+3` 会报什么错？ |
| D2 | 控制流（if/for/while） | 官方教程第4章 + CS50P Lecture 1 | Exercism 3-5道条件/循环题 | break 和 continue 跳到了哪里？ |
| D3 | 函数定义与参数 | 官方教程第4.6节 + CS50P Lecture 3 | Exercism 函数相关题 | 默认参数为什么不能用可变对象？ |
| D4 | 数据结构（list/dict/set） | 官方教程第5章 + Real Python "Lists" 和 "Dictionaries" 文章 | Exercism 列表/字典题 | list 和 dict 什么时候该用哪个？ |
| D5 | 文件操作与错误处理 | 官方教程第7-8章 + Automate 第8-9章 | Automate 实践项目：读写一个文本文件 | with 语句做了什么？为什么不用手动 close？ |
| D6 | 实战项目 | Automate 第12-13章（网页抓取/Excel操作） | 跟着 Automate 完成一个小项目 | 项目中哪个环节卡住了？为什么？ |
| D7 | 综合复盘 + 面向对象初探 | 官方教程第9章（前半） | 用学到的知识独立写一个小工具 | 回顾 D1-D6，哪些概念还不够熟练？ |

**资源搭配原则**：
- **官方教程**是主线，每天的第一小时跟着它走
- **CS50P** 是深度补充，看视频时不要只是"看"，要跟着敲代码
- **Real Python** 是专题工具，只在某个概念没搞懂时才去搜
- **Automate** 是实战引擎，Day 5-6 跟着做真实项目
- **Exercism** 是练习场，每天做 3-5 题保持手感

**输出文件**：`templates/resource-path.html` — 可视化的资源卡片 + 天级学习路径页面。

### Stage 3: 五等级进阶路线图

**目的**：把学习目标拆解为清晰的里程碑，让进步可感知。

#### 3.1 五个等级的定义

| 等级 | 名称 | 描述 | 标志 |
|------|------|------|------|
| L1 | 完全新手 | 零基础，第一次接触 | 能跟着示例敲出代码 |
| L2 | 语法入门 | 掌握了基本语法和概念 | 能独立完成简单练习 |
| L3 | 熟练应用 | 能组合多个概念解决问题 | 能完成小型项目 |
| L4 | 深入理解 | 理解底层原理和设计模式 | 能优化和重构代码 |
| L5 | 独立项目 | 能从零设计和实现完整项目 | 能做出可交付的作品 |

#### 3.2 每个等级的输出内容

对于每个等级，必须输出以下内容：

1. **应该掌握什么**：该等级的核心知识点清单（5-10 项）
2. **常见错误**：该等级最容易犯的 5-8 个错误
3. **实践任务**：1-2 个该等级的标志性练习/项目
4. **晋级标准**：满足什么条件才能进入下一等级（可量化）

#### 3.3 晋级标准的写法

晋级标准必须是**可量化、可验证**的：

- ❌ 不好的标准："理解了函数"
- ✅ 好的标准："能独立写出带参数、返回值和默认值的函数，并解释作用域"

**示例晋级标准**：

| 从 → 到 | 晋级标准 |
|---------|----------|
| L1 → L2 | 能独立写出包含变量、条件判断和循环的 20 行以内程序 |
| L2 → L3 | 能使用列表和字典完成数据处理和统计任务 |
| L3 → L4 | 能使用函数和模块组织代码，写出可读性良好的程序 |
| L4 → L5 | 能独立设计并完成一个包含文件读写、错误处理和用户交互的完整项目 |

#### 3.4 输出：等级路线图

**输出文件**：`templates/level-roadmap.html` — 可视化的五等级路线图，每个等级有详细说明、常见错误和晋级标准。

### Stage 4: 苏格拉底式逐个问题测验

**目的**：通过"一问一答"的方式检验理解，当场纠正错误，填补盲区。

#### 4.1 测验流程

```
开始 → 从简单问题问起 → 用户回答 → 评分+反馈 → 解释盲区 → 下一题（更难）→ 重复 5 题 → 总结
```

#### 4.2 评分标准

每道题按以下维度评分（满分 10 分）：

| 维度 | 权重 | 说明 |
|------|------|------|
| 正确性 | 40% | 核心答案是否正确 |
| 完整性 | 30% | 是否遗漏了重要细节 |
| 表达清晰度 | 20% | 解释是否清楚、有条理 |
| 深度 | 10% | 是否触类旁通、举一反三 |

#### 4.3 反馈模板

每次用户回答后，按以下结构反馈：

```
【评分】X / 10

【哪里对】
- 你正确指出了...
- ...这部分理解很到位

【哪里错】
- ...的理解有误，实际上...
- 你漏掉了...这一点

【哪里不完整】
- 你还可以补充...
- 如果考虑到...会更全面

【重新解释你没掌握的部分】
（用更通俗/不同角度重新讲解用户没掌握的概念）
```

#### 4.4 题目设计原则

- 5 道题，从易到难
- 每道题对应一个核心概念
- 第一题必须是该主题最基础的概念（建立信心）
- 最后一题必须是综合应用或常见陷阱（检验真实水平）
- 题目类型：概念识别 → 代码预测 → 找错改错 → 场景应用 → 综合设计

#### 4.5 何时进入测验

两种触发时机：
1. **学完一个等级后**：检验该等级是否掌握牢固
2. **用户主动要求**："考考我" / "帮我测试一下"

### Stage 5: 费曼学习法

**目的**：通过"用自己的话把概念讲给别人听"来检验真正的理解程度。讲不清就是没懂。通过多轮"讲解→反馈→重讲"逼近真正理解，最后用举一反三验证迁移能力。

> **与苏格拉底式测验的区别**：苏格拉底式是"你问我答"（被动检验），费曼学习法是"我讲你听"（主动输出）。两者互补：苏格拉底查盲区，费曼验深度。

#### 5.1 费曼学习法流程

```
AI 用 12 岁能听懂的话解释概念
  → 用户用自己的话讲回去
  → AI 从 4 个维度反馈
  → 用户修复问题，重新讲
  → 重复直到通过
  → 举一反三测试（迁移到新场景）
  → 通关总结
```

#### 5.2 AI 讲解原则

- **用比喻**：把抽象概念映射到日常事物（如"变量是贴纸，不是盒子"）
- **不用术语**：12 岁小孩能听懂的话，不出现任何专业名词
- **分层递进**：先讲核心比喻，再用代码验证，最后总结一句话
- **制造对比**：用"你以为是这样，但其实是这样"的反转加深记忆

#### 5.3 四维度反馈标准

用户讲完后，AI 从以下 4 个维度逐一反馈：

| 维度 | 检查什么 | 反馈方式 |
|------|----------|----------|
| **讲对了什么** | 核心比喻、关键逻辑、因果关系是否正确 | 明确肯定，指出具体哪句话对 |
| **漏了什么** | 是否遗漏了重要的原因、条件、边界 | 指出缺了什么，解释为什么重要 |
| **混淆了什么** | 两个概念是否搞混了、因果关系是否颠倒 | 指出混淆点，对比两者的区别 |
| **用了高级但自己没真懂的词** | 是否用了术语来掩盖理解缺口 | 指出该词，要求用大白话重新讲 |

#### 5.4 重讲触发条件

只要以下任何一项出现，就必须重讲：

- ❌ 核心比喻搞错（如玩具和贴纸搞反）
- ❌ 关键操作混淆（如 `b = 4` 和 `b.append(4)` 分不清）
- ❌ 用了术语但解释不了
- ❌ 总结句自相矛盾

重讲时，AI 明确列出"这次要修复的 N 个问题"，用户针对性修复，不需要从头再来。

#### 5.5 举一反三测试

当用户连续通过讲解轮次后，AI 抛出一个**新场景**（用同学过的概念，但换一个数据类型/情境），测试用户能否迁移：

- 给一段代码，问"结果是什么？为什么？"
- 用户必须用之前学到的原理推理，不能靠背
- 如果答对 → 通关；如果答错 → 回到讲解轮次

#### 5.6 通关标准

用户必须同时满足：
1. 核心比喻正确、无混淆
2. 能解释"为什么"（不只是"是什么"）
3. 总结句无自相矛盾
4. 举一反三题答对且推理过程正确

#### 5.7 完整示例：变量与赋值（4 轮费曼学习）

以下是一个真实的 4 轮费曼学习完整记录，展示从"有错"到"通关"的全过程。

**概念**：变量与赋值（Python）

**AI 初始讲解（12 岁版）**：

> 想象你房间里有一堆**玩具**（这些就是数据，比如数字 `5`、文字 `"你好"`、列表 `[1,2,3]`）。
>
> 你手里有一沓**贴纸**（这些就是变量名，比如 `a`、`b`、`name`）。
>
> 写 `a = 5` 不是把 `5` 塞进盒子，而是**在贴纸上写 `a`，贴到 `5` 这个玩具上**。
>
> 变量是贴纸，不是盒子。
>
> `b = a` 不是复制玩具，而是**又拿一张贴纸写 `b`，贴到同一个玩具上**。
>
> `b = 10` 是**把 `b` 贴纸撕下来，贴到 `10` 上**。`a` 不受影响。
>
> 但 `b.append(4)` 是**直接在玩具上动手脚**，贴纸没动，所有贴在这个玩具上的变量都看得到变化。
>
> 为什么？数字不可变（只能换贴纸），列表可变（可以改玩具）。

---

**第 1 轮：用户讲述**

> 房间里有一堆玩具，这些就是变量名。手中有一沓贴纸，这些就是变量。写 A=50，在纸上写下 A，贴到 5 上面。变量是贴纸不是盒子。B=A 不是复制玩具，是贴到同一个玩具上。B=10 是撕贴纸，A 还是 5。列表不一样，B 和 A 在同一个列表上，B 等于 4……一句话总结：复制是贴贴纸，不是复制玩具。

**AI 反馈**：

| 维度 | 反馈 |
|------|------|
| 讲对了 | 核心比喻抓住，`b=a` 不是复制、`b=10` 是撕贴纸、列表 append 是改玩具——都对 |
| 混淆了 | **最大问题**：总结里把"赋值"说成了"复制"。贴贴纸恰恰不是复制。应说"赋值是贴贴纸，不是复制玩具" |
| 混淆了 | `A=50` 后面又说贴到 `5`，前后矛盾 |
| 漏了 | 只讲了"是什么"，漏了"为什么列表和数字表现不同"——数字不可变，列表可变 |
| 高级词 | 用了 "passin" 之类的术语，给 12 岁小孩解释不需要任何术语 |

**修复清单**：
1. 把"复制"改成"赋值"
2. 加上可变/不可变解释
3. 数字前后一致

---

**第 2 轮：用户重讲**

> 玩具就是变量名，贴纸就是变量。A 等于 5，贴到 5 上面。赋值是贴贴纸不是复制玩具。B 等于 A 是又拿一张贴纸贴到同一个玩具上。B 等于 10 是撕贴纸。列表不一样，A 等于 123，B 等于 A，B 等于 4，不是撕贴纸而是直接修改列表……为什么列表变数字不变？因为数字不可变，列表可变。总结：赋值是贴贴纸，不是复制玩具。

**AI 反馈**：

| 维度 | 反馈 |
|------|------|
| 讲对了 | "赋值"用对了，可变/不可变方向对了 |
| 混淆了（严重） | **玩具和贴纸搞反了**：说"玩具就是变量名，贴纸就是变量"——完全反了。玩具=数据，贴纸=变量名 |
| 混淆了（严重） | **`b=4` 和 `b.append(4)` 混淆**：说"B 等于 4"是赋值（撕贴纸），不是 append（改玩具）。`b=4` 会让 B 离开列表，A 完全不受影响 |
| 混淆了 | `b=a` 说成"移动"贴纸，实际是"新增"一张 |
| 漏了 | 可变/不可变与 `=` vs `.append()` 的关系没串起来 |

**修复清单**：
1. 玩具=数据，贴纸=变量名，别搞反
2. 列表那步是 `b.append(4)` 不是 `b=4`
3. `b=a` 是新增贴纸不是移动
4. 把可变/不可变和 `=` vs `.append()` 串起来

---

**第 3 轮：用户重讲**

> 房间里有一堆玩具，这些就是程序中的数据，比如数字 5、文字你好、列表 123。手中有一沓贴纸，这些就是变量名。A 等于 5，在纸上写下 A，贴到 5 这个玩具上。变量是贴纸不是盒子。B 等于 A，又拿一张贴纸贴到同一个玩具上。B 等于 10，把 B 这张贴纸撕下来重新贴到 10 上，A 还是 5。列表不一样，A 等于 123，B 等于 A，B.append(4)，不是撕贴纸而是直接在列表玩具上动手加了一个 4，贴纸没变玩具变了，A 也贴在这个玩具上，所以 A 变成了 1234。为什么列表变数字不变？因为数字不可变，列表可变。总结：赋值是贴贴纸，不是复制玩具，改贴纸不影响别人，但直接改玩具，所有贴在同一玩具上的变量都会看到变化。

**AI 反馈**：

| 维度 | 反馈 |
|------|------|
| 全部修复 | 玩具=数据✓ 贴纸=变量名✓ `b.append(4)`✓ 新增贴纸✓ 赋值≠复制✓ |
| 差最后一层 | 可变/不可变与操作类型的关系没说透：不可变→只能换贴纸(`=`)；可变→可以改玩具(`.append()`)。这两件事是一枚硬币的两面 |

---

**举一反三测试**

AI 抛出新场景：

```python
a = "hello"
b = a
b = "world"
```

> 跑完后 `a` 是什么？`b` 是什么？为什么？

**用户回答**：

> A 等于 hello，B 等于 A，B 等于 world。因为 B 等于 world 是把 B 这个贴纸从 hello 上撕下来，重新贴到 world 上。所以 A 不变，还是 hello。B 已经把贴纸撕下来贴到了 world 上，所以 B 是 world。

**AI 反馈**：

> **完全正确。满分。**
>
> 你没有犹豫，直接判断 `b = "world"` 是撕贴纸。这说明你隐含地用到了规则：字符串是不可变的，所以 `b = "world"` 只能是换贴纸。你做到了从数字 `5` 迁移到字符串 `"hello"`——两者都是不可变的。

---

**通关总结**：

| 轮次 | 状态 | 关键问题 |
|------|------|---------|
| 第 1 轮 | 基本框架对，细节有误 | "复制"和"赋值"混用，漏了可变/不可变 |
| 第 2 轮 | 进步明显，出现新混淆 | 玩具贴纸搞反，`b=4` 和 `b.append(4)` 混淆 |
| 第 3 轮 | 四个问题全修 | 差最后一层连接 |
| 第 4 轮（举一反三） | 通关 | 能迁移到新场景 |

**核心三句话**：
1. 变量是贴纸，不是盒子
2. 赋值 `=` 是换贴纸，方法 `.append()` 是改玩具
3. 不可变类型只能换贴纸，可变类型可以改玩具
